# Нарезка роликов из стрима

Берёт длинный стрим, вырезает кусок по таймкодам, в конце плавно **приглушает звук
и затемняет картинку**, а затем показывает **концовку — размытую, с музыкой**.

Нужен `ffmpeg` в PATH (уже есть) и Python 3.

## Окошко (проще)

Двойной клик по **Нарезка роликов.bat** — откроется окно программы.
Батник сам проверит, что на месте ffmpeg и Python, и подскажет, если чего-то нет.
Из командной строки то же самое: `py gui.pyw`

Выбираешь стрим, концовку, музыку и папку вывода → добавляешь отрезки
(начало / конец / имя файла) → «Сделать ролики». Можно накидать сразу
десяток отрезков из одного шестичасового стрима и уйти. Настройки
запоминаются в `settings.json`.

## Командой

```bash
py clipmaker.py -i stream.mp4 -s 1:23:45 -e 1:31:10 --outro outro.mp4 --music track.mp3 -o clip01.mp4
```

Время пишется как `1:23:45`, `23:45`, `3725` или `3725.5`.
Вместо конца можно указать длительность: `-e +7:25`.

### Параметры

| Ключ | Что делает | По умолчанию |
|---|---|---|
| `-i` | исходный стрим | — |
| `-s` / `-e` | начало / конец (или `+длительность`) | — |
| `-o` | выходной файл | — |
| `--outro` | файл концовки | нет (тогда просто нарезка) |
| `--music` | музыка поверх концовки, заменяет её звук | звук концовки |
| `--music-volume` | громкость музыки (0.5 = тише вдвое) | 1.0 |
| `--fade` | сколько секунд длится затемнение и приглушение | 1.5 |
| `--blur` | сила размытия концовки, 0 = без размытия | 20 |
| `--dark` | дополнительно затемнить концовку, 0..1 | 0 |
| `--width/--height/--fps` | формат вывода | как в стриме |
| `--crf` | качество, меньше = лучше и тяжелее | 20 |
| `--gpu` | кодировать на видеокарте NVIDIA (быстрее) | выкл |
| `--dry-run` | только показать команду ffmpeg | — |

Музыка короче концовки — зациклится; длиннее — обрежется. Концовка сама
появляется из чёрного и уходит в чёрное, музыка нарастает и затухает вместе с ней.
Концовка приводится к формату основного ролика, так что 1080p-концовка на
720p-стриме подхватится нормально.

## Как устроено внутри

Кусок стрима и концовка кодируются **отдельными проходами** (простыми `-vf`/`-af`),
а потом склеиваются без перекодирования. Так сделано не от красоты: в ffmpeg 9.0
граф, где в одном `filter_complex` сидят и видео-, и аудиоветка, на длинных
кусках начинает молча выбрасывать видеокадры — на 21-минутном отрезке доходило
до 55 000 кадров вместо 78 000, причём число плавало от запуска к запуску.
Картинка при этом замирает, а звук идёт дальше. Разделение проходов это лечит.

Дополнительно программа следит за счётчиком `dup` у ffmpeg и пишет
«ВНИМАНИЕ», если продублированных кадров набралось больше секунды —
чтобы подобное больше не проходило незамеченным.
