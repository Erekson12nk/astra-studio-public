# clipper

Конвейер автонарезки коротких роликов из длинных видео.

**Работает бесплатно.** Оценка фрагментов вынесена в подключаемый движок:
локальная модель, встроенные правила без модели вообще, или платный API —
на выбор. Остальной конвейер от выбора не зависит.

**Это фаза 1: обучения ещё нет.** Но всё, что система делает, пишется в SQLite:
кандидаты, признаки, ваши оценки, попарные сравнения. Это фундамент, на котором
фазы 2–4 обучат персональную модель вкуса.

## Как это устроено

```
видео → звук → расшифровка → окна → ДВИЖОК выбирает → границы к паузам → рендер
        ffmpeg   Whisper              ↑                пословные метки    ffmpeg
                     ↓         heuristic / ollama /          ↓
                  кеш JSON     openai-compat / claude      SQLite ← ваши оценки
```

Три решения, которые стоит понимать:

**Расшифровывается только звуковая дорожка.** Whisper видеоряд не смотрит.
Час видео — это 30–60 МБ звука вместо нескольких гигабайт.

**Движок возвращает номера реплик, а не секунды.** Тайм-коды подставляются из
расшифровки. Если просить модель оперировать секундами, она их выдумывает — это
одинаково верно для облачных и локальных моделей.

**Ответ разбирается терпимо.** Маленькие локальные модели заворачивают JSON в
markdown, добавляют болтовню и ставят висячие запятые. Парсер это переживает.

## Движки

| Движок | Стоимость | Что нужно | Качество |
|---|---|---|---|
| `heuristic` | 0 | ничего | низкое, но мгновенно |
| `ollama` | 0 | установить Ollama + модель | среднее |
| `openai-compat` | 0 | LM Studio или llama.cpp | среднее |
| `claude` | ~12 коп/час видео | ключ API | высокое |

Посмотреть, что доступно прямо сейчас:

```bash
py cli.py backends
```

По умолчанию стоит `heuristic` — он работает сразу, без установки чего-либо.

### Бесплатный путь с нормальным качеством: Ollama

```bash
winget install Ollama.Ollama
```

```bash
ollama pull qwen3:8b
```

Модели под ваши ~5.5–7 ГБ свободной видеопамяти (4-битная квантовка):

| Модель | Память | Замечание |
|---|---|---|
| `qwen3:8b` | ~5.2 ГБ | **установлена по умолчанию**, хорошо знает русский |
| `qwen2.5:7b-instruct` | ~4.7 ГБ | предыдущее поколение, полегче |
| `llama3.1:8b` | ~4.9 ГБ | универсальная |
| `qwen3:4b` | ~2.6 ГБ | если памяти мало; слабее |

Qwen3 — гибридная reasoning-модель: она умеет рассуждать вслух в блоке
`<think>` перед ответом. Для извлечения структурированного ответа это лишняя
трата времени на локальном железе, поэтому рассуждение отключается
(`"think": false`), а парсер вырезает такие блоки, если они всё же появятся.

Названия и версии в этой области меняются быстро — сверяйтесь с `ollama list`
и библиотекой моделей Ollama.

**Замеры на этой машине** (RTX 3050 8 ГБ, `qwen3:8b` Q4_K_M, контекст 8192):

```
модель в памяти:   6.2 ГБ, 100% на GPU, свободно остаётся ~850 МБ
окно расшифровки:  ~55 сек на ответ
час видео:         ~15 окон по 4 мин → примерно 13-15 минут работы модели
```

Запас по видеопамяти минимальный. Если параллельно открыт браузер или игра,
Ollama **не упадёт, а тихо перенесёт часть слоёв на процессор** — и станет
в десятки раз медленнее, без единого сообщения об ошибке. Поэтому перед
запуском проверяется остаток памяти и выводится предупреждение. Если памяти
не хватает, берите `qwen3:4b` или уменьшайте `CLIPPER_NUM_CTX`.

Запуск:

```bash
py cli.py run "видео.mp4" --backend ollama
```

## Графический интерфейс

Двойной клик по **`Нарезка роликов.bat`** — откроется окно, консоль не нужна.
Зависимостей нет: tkinter входит в состав Python.

Три вкладки:

**Нарезка** — выбрать файлы или папку, движок, параметры, нажать «Запустить».
Ход работы виден в логе, кнопка «Остановить» прерывает между шагами (оборвать
уже отправленный запрос к модели нельзя, но ждать все оставшиеся окна не придётся).

**Оценка** — два клипа рядом, кнопки «Посмотреть» открывают их в плеере,
внизу «A лучше / Одинаково / B лучше». Пары подбираются там, где движок сомневается,
всегда из одного исходника, и уже сравнённые не повторяются.

**Все клипы** — таблица со всеми кандидатами. Двойной клик открывает клип,
кнопки 1–5 ставят оценку, «🗑 Удалить» отклоняет. Клик по заголовку колонки
сортирует, повторный клик переворачивает порядок; неоценённые всегда остаются
в конце. Фильтры сверху: все / только с файлом / только оценённые / удалённые.

Колонка **статус** показывает состояние файла:

| Статус | Что значит |
|---|---|
| `новый` | отрендерен в последнем прогоне |
| `старый` | файл есть, но от более раннего прогона |
| `удалён` | вы отклонили его, оценка 0, файл убран |
| `нет файла` | **не сбой** — кандидат найден, но в top-N не попал |
| `пропал` | запись о рендере есть, а файла на диске нет |

**Про `нет файла`.** Движок находит сотни кандидатов на длинном видео — на
шестичасовой записи их бывает больше двухсот. Режутся только лучшие: `top_n`
штук выше порога `CLIPPER_MIN_SCORE`. Остальные остаются в базе как данные и
файла никогда не имели. Список показывает **всех кандидатов**, а не только
нарезанное, поэтому строк там всегда намного больше, чем клипов на диске.
Хотите видеть только готовое — фильтр «только с файлом».

Досоздать недостающие можно без повторного отбора:

```bash
py cli.py render --video 2 --top 50
```

Вкладка «Оценка» — то, ради чего интерфейс вообще писался. Датасет копится
только тогда, когда сравнивать не лень, а набирать в консоли
`py cli.py compare 12 15 --winner a` лень становится на третий раз.
Здесь это два клика.

Консольный вариант никуда не делся и делает всё то же самое.

## Использование из консоли

Найти фрагменты, но не тратить время на рендер — так удобно подбирать движок:

```bash
py cli.py run "C:\видео\стрим.mp4" --no-render
```

Полный прогон, вертикальный формат с субтитрами:

```bash
py cli.py run "C:\видео" --vertical --subs --top 15
```

Посмотреть, что нашлось:

```bash
py cli.py list
```

Расшифровка кешируется, поэтому сменить движок и прогнать заново — быстро:
второй раз Whisper не запускается.

## Порядок пар в окне оценок

Движок насыщает оценку: на живой базе 77 клипов из 79 получили ровно 9.0.
Подбор пар сортировался по близости оценок — то есть по сплошным нулям, — и
стабильная сортировка каждый раз возвращала одни и те же самые старые пары.
Свежесмонтированные клипы не показывались никогда.

Теперь первым делом смотрится, кого ещё мало сравнивали, потом разница
оценок, потом свежесть; вдобавок один клип не занимает больше двух пар в
выдаче, иначе весь список вырождался в «самый свежий против всех».

Ещё одна причина той же беды: `renders` копила по записи на каждый рендер,
и после пере-рендера или `adopt` один кандидат числился дважды. JOIN
размножал строки, и клип мог встать сам против себя. Теперь запись одна на
кандидата, а старые дубли вычищаются при `py cli.py adopt`.

## Кеш

Фрагментированный контейнер перекладывается один раз, и переложенная копия
весит столько же, сколько исходник. За пару стримов в `C:\clipper-work\cache`
набирается несколько десятков гигабайт, и само оно оттуда не уходит.

```bash
py cli.py cache            что накопилось, по видам и с размерами
py cli.py cache --clean    убрать перекладки, у которых не осталось исходника
py cli.py cache --all      убрать весь кеш целиком
```

Без флагов команда ничего не удаляет — только показывает. `--clean`
безопасен: он трогает лишь перекладки, чей исходник вы уже удалили, — они
всё равно ни на что не годятся. Перекладку живого стрима стоит держать,
пока режете из него клипы: с ней клип вырезается за секунды.

Расшифровки в кеше не лежат: они хранятся рядом со стримом
(`имя.mp4.speech.json`), и `--all` их не тронет.

## Как копить данные для обучения

Это главное, ради чего стоит пользоваться системой с первого дня. Без данных
фаза 3 не наступит никогда.

**Попарные сравнения важнее звёздочек.** Абсолютная оценка у человека плывёт:
сегодня вы ставите 4, через неделю тому же ролику 3. Относительное сравнение
устойчиво — именно на нём обучается модель предпочтений.

Спросить, какие пары стоит сравнить (берутся те, где движок менее всего уверен —
сравнивать очевидно лучшее с очевидно худшим бесполезно):

```bash
py cli.py pairs
```

Записать результат:

```bash
py cli.py compare 12 15 --winner a
```

Абсолютная оценка тоже пишется, если так удобнее:

```bash
py cli.py rate 12 5
```

Добавить референсные ролики — готовые удачные клипы. Это решает проблему
холодного старта: каждый референс даёт положительные примеры, а случайные
фрагменты тех же исходников — отрицательные:

```bash
py cli.py ref "C:\удачные\клип.mp4" --note "то, что зашло"
```

Сколько накоплено:

```bash
py cli.py stats
```

В базу пишется, **какой движок** выставил оценку. Это важно: позже надо будет
отличать суждения эвристики от суждений модели, иначе датасет смешается.

## Настройка

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `CLIPPER_BACKEND` | `heuristic` | движок оценки |
| `CLIPPER_LOCAL_MODEL` | `qwen3:8b` | модель для ollama / openai-compat |
| `OLLAMA_HOST` | `http://localhost:11434` | адрес Ollama |
| `CLIPPER_OPENAI_URL` | `http://localhost:1234` | адрес OpenAI-совместимого сервера |
| `CLIPPER_NUM_CTX` | `8192` | контекст локальной модели |
| `CLIPPER_TIMEOUT` | `600` | сколько ждать ответа локальной модели, сек |
| `CLIPPER_MODEL` | `claude-opus-5` | модель Claude |
| `CLIPPER_EFFORT` | `medium` | глубина рассуждения: low/medium/high |
| `CLIPPER_WHISPER` | `large-v3` | модель расшифровки |
| `CLIPPER_LANG` | `ru` | язык (пусто — автоопределение) |
| `CLIPPER_MIN` / `CLIPPER_MAX` | `20` / `90` | длительность клипа, сек |
| `CLIPPER_MIN_SCORE` | `5.0` | ниже этой оценки клип не рендерится |
| `CLIPPER_CHUNK` | `0` (авто) | окно расшифровки, мин |
| `CLIPPER_WORK` | `C:\clipper-work` | рабочая папка |
| `CLIPPER_OUT` | `C:\clipper-work\out` | куда складывать клипы |

**Про размер окна.** `0` означает «выбрать под движок»: облачной модели даётся
8 минут, локальной 4 — у неё меньше контекста и внимание рассеивается быстрее.
Задавайте вручную, только если понимаете, зачем.

**Про контекст локальной модели.** Без явного `num_ctx` Ollama берёт маленький
контекст по умолчанию и **молча обрезает** расшифровку — фрагменты из конца окна
просто не рассматриваются. Поэтому он выставляется всегда.

**Про рабочую папку.** По умолчанию `C:\clipper-work`, и это не случайно.
Диск `D:` — это Storage Spaces поверх SMR-диска, он даёт многосекундные залипания
на потоковой записи. Видеообработка пишет много. Держите рабочие файлы на NVMe.

## Что дальше

| Фаза | Что делает | Состояние |
|---|---|---|
| 1 | Конвейер + подключаемые движки | **готово** |
| 2 | Накопление датасета: оценки и сравнения | идёт при использовании |
| 3 | Реранкер поверх кандидатов движка | **включён по умолчанию**, данных мало |
| 4 | Персональная модель предпочтений | после фазы 3 |

```
py cli.py train                     обучить на ваших сравнениях и оценках
py cli.py list --video 1            порядок с учётом модели
py cli.py run "стрим.mp4"           отбор с учётом модели
py cli.py run "стрим.mp4" --no-rerank   без модели, только движок
```

**Обученная модель подхватывается сама** — `run`, `render` и `list` берут её
из `rerank.json`, отдельного флага для этого не нужно. Про это говорится
строкой вида «модель вкуса на 312 парах, точность 0.63».

**Модель своя у каждого профиля** и лежит рядом с его базой оценок:
`profiles/<имя>/rerank.json`. Вкус у стримеров разный, и одна общая модель
усредняла бы их в кашу. Без профиля путь прежний — `rerank.json` в рабочей
папке. Прежняя общая модель переезжает к активному профилю сама, один раз.

Само собой она включается не всегда. При обучении откладывается четверть
пар, и если на них модель не обыграла движок, она остаётся лежать, а порядок
берётся движковый — с объяснением, почему. Настоять можно флагом `--rerank`,
отказаться — `--no-rerank`.

Обучается логистическая модель Брэдли-Терри на разностях признаков. В пары
идут и попарные сравнения, и оценки: клип с четвёркой считается лучше клипа
с тройкой. Четверть пар откладывается и в обучении не участвует — на них
модель и проверяется.

**Про базовую линию.** Точность движка считается с ничьими по половине балла.
Это важно: `qwen3` насыщает оценку и почти всем ставит одно и то же, а если
считать равенство промахом, базовая линия падает в ноль и реранкер обыгрывает
её не глядя. С честным счётом насыщенный движок даёт ровно 0.50 — монетку,
и это правильно: он действительно отказался упорядочивать.

Модель сохраняется, только если обыграла движок на отложенных парах. Если этих
пар меньше сорока, программа отдельно предупреждает, что разница может быть
случайной.

Реранкер фазы 3 обязан обыгрывать текущий движок на отложенной выборке. Если не
обыгрывает — он не нужен, и это нормальный результат эксперимента. Движок
`heuristic` удобен как нижняя граница: обученная модель обязана быть лучше него.

**Распределение между машинами** отложено, но заложено: `pipeline.process()`
принимает самодостаточный `Task` и не трогает глобальное состояние. Когда дойдут
руки, вместо цикла по задачам встаёт очередь, а работнику отправляется звуковая
дорожка, а не исходник.

## Равные оценки и разнос по стриму

`qwen3:8b` насыщает шкалу. Замер на стриме 1 сентября (239 мин, 132 кандидата):
оценка приняла **четыре значения** — 10.0 у одного, 9.0 у пятидесяти, 8.0
у семидесяти восьми, 7.0 у трёх. Мест в выдаче тридцать, значит двадцать
девять из них выбираются внутри плато, где порядка нет.

А `ORDER BY model_score DESC` без второго ключа отдаёт строки в порядке
вставки, то есть по времени. Результат на том прогоне был буквальный:
**всё до 2:00:40 взято, всё после отброшено, без единого исключения.**
Половина стрима — 68 кандидатов, из них 22 с той же оценкой 9.0 — пропала
только за то, что позже.

`scoring.spread` режет стрим на восемь частей и обходит их по кругу, беря
из каждой лучшее по очереди. На тех же данных:

```
top-20, кандидатов по получасам
   было:  8 11 0 0 1 0 0 0
   стало: 3 3 4 2 2 2 2 2
```

Средняя оценка движка при этом **не изменилась** (9.05 против 9.05) — что
и доказывает, что отброшенные были ровно такими же. Момент с 10.0 остаётся
на месте: внутри своей части он первый.

Восемь частей — не догма, но пусть их будет меньше, чем просят клипов
(`buckets = min(8, top)`), иначе часть корзин просто некем заполнить.

Первая версия обходила корзины подряд, набивая каждую до лимита `top/buckets`.
Так последняя корзина оставалась пустой: лимит с запасом округляется вверх,
и места кончались раньше, чем очередь доходила до конца. Обход по кругу
от этого свободен.

## Ваши клипы как пример вкуса

`py cli.py picks <папка>` берёт папку с клипами, которые вы смонтировали
сами, находит для каждого кандидата по таймкоду в имени и записывает
сравнения «взятое лучше невзятого». Это и есть тот сигнал, которого
реранкеру не хватало: у него было три десятка пар, а одна папка своих
клипов даёт сотни.

**Допущение здесь одно и оно названо вслух:** невзятое считается худшим,
хотя вы могли до него просто не дойти. Поэтому выведенное помечается
в базе как `выбор`, ваше ручное — как `рука`, и `py cli.py picks --forget`
снимает всё выведенное, не трогая ручное.

Колонка `source` появилась миграцией: старые базы получают её со значением
`рука`, то есть всё, что было накоплено руками, таковым и остаётся.

## Выгрузка берёт один стрим

`export` пишет файл таймкодов, а файл таймкодов всегда применяется к одному
видео — значит смешивать стримы в нём нельзя в принципе. Раньше `export` без
`--video` брал кандидатов **из всех** видео базы, отсортированных по оценке.
На базе из шести стримов это дало 30 моментов, из которых нужному стриму
принадлежал один: остальные 29 указывали на чужие записи, причём 17 — на
исходник, которого на диске уже нет. Клипы при этом отрендерились бы молча:
astra просто вырезает названные времена из того файла, что ей дали, и
получились бы тридцать клипов правильной длины и чужого содержания.

Теперь без `--video` берётся последний обработанный стрим, и об этом сказано
в выводе; если в базе есть другие — сказано и про них. `list` без `--video`
предупреждает, что показывает вперемешку. Сторож — `tests/export_test.py`,
в нём есть та самая ловушка: у чужого стрима оценки выше, и он не должен
перетягивать.

Правило на будущее: **всё, что уходит в один файл или в один рендер, должно
быть привязано к одному видео явно.** У `render` так и было — `--video`
там `required`.

## list показывает то же, что уходит в export

Порядок собирается в одном месте — `cli.ranked` (модель вкуса, иначе
движок) и `cli.choose` (разнос по стриму). Раньше модель вкуса
подхватывали `run`, `render` и `list`, но не `export`: их top-30 совпадали
**на 8 из 30**, и все оценки, которые вы проставляли, на итоговую выгрузку
не влияли вообще — рабочий путь идёт через `export`. Теперь у `export`
есть свои `--rerank` / `--no-rerank`, а `py cli.py list --top 20` помечает
звёздочкой ровно то, что уйдёт в файл.

## Известные ограничения

- **`heuristic` — это правила, а не понимание.** Он ловит плотность речи,
  содержательные маркеры и отсекает оргмусор, но смысла не видит. Годится
  проверить конвейер и как нижняя граница, не как рабочий инструмент.
- **Локальные модели на 7–8B заметно слабее** облачных в суждениях о вкусе,
  особенно на русском. Это компромисс, а не паритет.
- **Кадрирование в 9:16 грубое**, по центру кадра. Слежения за лицом нет.
- **Оценка идёт только по тексту.** Смех, пауза, интонация, выражение лица
  в решении не участвуют. Это следующее, что стоит добавить.
- **Границы уточняются по паузам в речи**, а не по монтажным склейкам. Для
  разговорного контента достаточно, для динамичного — нет.
- Рендер идёт с перекодированием: быстрая резка по ключевым кадрам промахивается
  мимо точки на секунды, а мы боремся за точность.
