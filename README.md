# Astra Studio

Настольное приложение для Windows, которое делает из стримов с Twitch готовые
видео. Оно следит за каналом стримера, после эфира само скачивает запись,
находит в ней удачные моменты, монтирует вертикальные шортсы 9:16 и длинные
«Ролики» и выкладывает на YouTube с закрытым доступом то, что вы одобрили.

Код на Python, интерфейс на Tkinter. Распознавание речи, поиск лиц, голосов
и моментов работают локально. Языковая модель нужна только для поиска
«по смыслу» и нескольких уточнений, и она тоже может быть локальной (Ollama,
LM Studio).

## Что умеет

- **Следить за эфиром.** Раз в минуту спрашивает Twitch, идёт ли стрим. Пока
  идёт, пишет звук эфира, чтобы потом закрыть им куски, которые Twitch заглушит
  в записи из-за музыки.
- **Брать запись сам.** После конца эфира ждёт, пока Twitch опубликует запись,
  скачивает её через `yt-dlp` и сразу режет. Записи эфиров, прошедших при
  выключенном компьютере, находит часовая проверка.
- **Распознавать речь** через faster-whisper. Кеш общий для всех частей
  программы, так что один файл не расшифровывается дважды.
- **Находить моменты** по всплескам громкости (быстро, без модели) или по смыслу
  расшифровки (эвристика, Ollama, OpenAI-совместимый сервер или Claude).
  Найденное сравнивается попарно, есть обучаемый реранкер.
- **Монтировать шортсы 9:16:** вебка сверху, геймплей снизу, караоке-субтитры
  по словам, заголовок, автоцензура мата в звуке и в субтитрах, вырезание пауз.
  Вебку программа находит по снимку из профиля стримера и отличает его лицо
  от чужих лиц на экране.
- **Собирать длинные «Ролики»** по играм (главы Twitch) и по реакциям
  в разговорной части стрима. В конце ролика картинка затемняется, идёт
  размытая концовка под музыку, рядом кладётся копия с заглушённым матом.
- **Чистить моменты:** вырезать донаты не по теме и места, где стример отошёл
  от компьютера.
- **Возвращать звук на места, заглушённые Twitch**, из своей записи эфира.
- **Выкладывать** одобренное по одному и по расписанию через браузер (мост
  к social-auto-upload), читать просмотры из YouTube Studio без API.
- **Учиться вкусу** на просмотрах своих выгрузок, ваших оценках и сравнениях.
- **Убирать за собой:** удалять старые записи, звук эфира и отработанные клипы,
  следить за свободным местом.
- Работать **фоновой службой в трее** сразу для нескольких стримеров.

## Как это работает

Ниже путь одного стрима от начала эфира до выгрузки. В автоматическом режиме
его ведут `core/service.py` (служба) и `core/autopilot.py` (автопилот одного
профиля). То же самое можно сделать руками в окне Студии.

```
эфир идёт ── сторож Twitch (GQL раз в минуту) ── streamlink пишет звук эфира
   │                    ▲
   │      анонс в публичном телеграм-канале будит сторожа
   ▼
эфир кончился ── ждём запись (до 20 попыток раз в 3 мин) ── yt-dlp качает
   ▼
расшифровка (faster-whisper, кеш имя.mp4.speech.json)
   ├── клипы:  поиск моментов → донаты / «отошёл» → монтаж 9:16 (astra)
   └── ролики: главы Twitch + реакции → донаты / «отошёл» → clipmaker
               → звук на мут Twitch → audioclean («без мата»)
   ▼
очередь «ждёт» ── вы одобряете ── выгрузка по расписанию ── просмотры ── вкус
```

### 1. Слежение за эфиром

Стример в программе — это профиль. В настройках автопилота профиля указываются
канал Twitch и, если нужно, публичный телеграм-канал с анонсами.

**Twitch.** Сторож (`live.Watcher`) раз в минуту спрашивает Twitch GQL
(`gql.twitch.tv`), есть ли у канала живой `stream` и когда он начался.
`Client-ID` в коде — общий публичный ключ сайта Twitch, а не личный. Как только
эфир пошёл, `streamlink` начинает писать **только звук** (`audio_only,worst`,
около 100 МБ в час) в папку `_эфир` рядом с папкой стримов. Если связь
оборвалась, пишется следующий кусок. Рядом с каждым куском лежит `.json`
с каналом, номером эфира и временем начала по часам компьютера. Если сторож
включился, когда эфир шёл уже больше двух минут, начало докачивается из записи
Twitch, которая ещё пишется.

**Телеграм.** `core/telegram.py` — не бот. Раз в две минуты он читает публичную
веб-страницу канала `t.me/s/канал`, без входа и без токенов, и ищет новые посты
со ссылками на трансляцию. Пост со ссылкой на свой Twitch сразу будит сторожа,
не дожидаясь очередной минуты: это запасной сигнал «стрим начался». Если ссылка
ведёт на другую площадку (YouTube, Kick, VK, GoodGame), `core/elsewhere.py`
записывает эту трансляцию целиком, вместе с видео, через `streamlink`, потому
что потом записи на площадке может и не быть. Пост без ссылки анонсом
не считается.

**Запасная проверка.** Раз в час и при запуске служба смотрит список записей
каждого канала. Так находятся эфиры, прошедшие при выключенном компьютере.
У нового стримера старые записи помечаются пропущенными (`skip_old`), и режутся
только эфиры после того, как его добавили.

### 2. Скачивание

Список записей канала берётся через `yt-dlp --flat-playlist`: последние
`look_back` записей, по умолчанию 5. Запись идущего эфира пропускается, её
возьмут после конца. Если в папке стримов уже лежит файл с номером записи
в имени, он не качается заново.

`core/fetch.py` вызывает `yt-dlp` с повторами (`--retries 20`,
`--fragment-retries 20`) и делает до 12 попыток, если обрывается связь. Если
обычный загрузчик не справился, второй заход идёт через ffmpeg. Прогресс,
скорость и остаток времени разбираются из вывода `yt-dlp`.

Ограничения:

- перед скачиванием проверяется свободное место (`min_free_gb`, по умолчанию
  60 ГБ). Если места мало, сначала запускается чистка. Если и после неё мало,
  запись ждёт следующего запуска;
- стримы режутся по одному. Служба, окно Студии и часовая задача делят один
  межпроцессный замок (`core/lock.py`), потому что видеокарта одна;
- `streams_per_run` (по умолчанию 1) задаёт, сколько записей обрабатывается
  за проход;
- если за 20 попыток Twitch так и не выложил запись, её подберёт обычная
  часовая проверка.

### 3. Расшифровка речи

`core/asr.py` — один загрузчик faster-whisper на весь репозиторий. Модели:
`tiny`, `base`, `small`, `medium`, `large-v3`, `large-v3-turbo` (по умолчанию).

- Расшифровка кешируется **рядом с исходником**, в файле `имя.mp4.speech.json`.
  Ключ кеша включает модель, размер файла, язык, beam и VAD. Поиск моментов,
  монтаж, цензура роликов и разметка реакций берут одну и ту же расшифровку.
- Монтаж astra не распознаёт каждый клип заново, а режет готовую расшифровку
  стрима по границам клипа. Исключения — вырезание пауз и вырезы внутри клипа:
  в этих случаях шкала времени меняется, и речь распознаётся заново.
- Каталоги cuBLAS и cuDNN (пакеты `nvidia-cublas-cu12` и `nvidia-cudnn-cu12`)
  регистрируются до импорта faster-whisper, а модель сначала проверяется
  пробным прогоном. Если с CUDA что-то не так, работа идёт на процессоре.

### 4. Поиск моментов

Движки бывают двух видов (`core/detect.py`):

| Вид | Движки | Что на входе | Что на выходе |
|---|---|---|---|
| звуковой | `loudness` | звук стрима | секунды начала и конца |
| текстовые | `heuristic`, `ollama`, `openai-compat`, `claude` | расшифровка | номера реплик |

**По громкости** (`core/loudness.py`) — мгновенно, без расшифровки и без
модели. Уровень звука считается окнами по 0.25 с в полосе речи и сравнивается
со скользящей базой. Оценка складывается из нескольких признаков: подъём
над фоном, резкость атаки, речь. Границы момента подтягиваются к тихим местам.
Уровни кешируются рядом с файлом. Автопилот по умолчанию ищет именно так.

**По смыслу** работает пакет `clipper`. Стрим режется на окна, и движок ставит
каждому фрагменту оценку от 0 до 10. Оценка отсекает мусор порогом, а порядок
среди оставшихся задаёт отдельная стадия сравнения:

- модели показывают по 6 фрагментов и просят расставить их от лучшего
  к худшему. В первом круге группы случайные, дальше в группу попадают соседи
  по силе (швейцарская схема). Пары сводятся моделью Брэдли-Терри
  (`clipper/compare.py`);
- пары сравнений пишутся в базу с пометкой `source = "модель"`, из них
  копятся данные для реранкера;
- если обученный реранкер (`core/rerank.py`) на отложенных парах точнее
  движка, порядок задаёт он.

Ответы маленьких моделей программа терпеливо разбирает: вырезает блок
`<think>` и markdown-обёртку, убирает висячие запятые.

Окно ещё прикидывает по найденному, **сколько примерно выйдет** шортсов
и больших роликов (`core/launch.estimate`). Ролик здесь — кусок стрима, где
хорошие моменты идут один за другим с промежутком не больше пяти минут.
Таких моментов должно быть хотя бы три, а сам кусок — длиннее шести минут.

### 5. Донаты и «отошёл»

Перед монтажом найденные моменты проверяются (`core/streamcheck.py`).
Проверки включаются галочками в профиле, отдельно для клипов и для роликов.

**Донаты** (`core/donations.py`, `core/jingle.py`, `core/voiceid.py`).
Донат узнаётся по звуку оповещения. У каждой суммы свой звук, образцы хранятся
в профиле, а поиск идёт корреляцией мел-спектрограммы с образцом. Голоса
различает модель CAM++ через sherpa-onnx: стример, «робот» (синтезатор,
который зачитывает донат) и все остальные. Голос робота запоминается по первому
найденному донату. Дальше программа определяет, где робот дочитал и что ответил
стример, а языковая модель решает, подходит ли донат к теме клипа. Если модели
нет, решает запасное правило по общим корням слов. Донат не по теме
вырезается. Если он занимает почти весь клип, клип выбрасывается.

**Отошёл** (`core/away.py`). Кадр берётся раз в 4 секунды через ffmpeg:
OpenCV на длинных записях Twitch видел только первый час. Сигналы такие: лица
нет в вебке дольше 20 секунд, кадр застыл (заставка), тишина, не слышно голоса
стримера, в расшифровке есть фразы вроде «щас вернусь» или «отойду». Вебка
ищется по снимку профиля. Отсутствие короче минуты не считается. Если стримера
нет больше половины клипа, клип убирается, иначе отсутствие вырезается
изнутри.

### 6. Монтаж 9:16

Монтирует движок `astra/auto_vertical_editor.py`. Окно и движок обмениваются
объектом `core.settings.Render`, а не строкой флагов. Автопилот запускает
движок отдельным процессом и передаёт ему файл таймкодов `_моменты.txt`
(формат описан в `core/handoff.py`).

- **Где вебка.** `core/webcam.py` ищет на кадре снимок вебки из профиля
  по приметам картинки (ORB и гомография на уменьшенном кадре), поэтому вебка
  находится, даже когда лица не видно. Перед пакетной нарезкой программа
  берёт по паре кадров из каждого клипа и собирает «якорь» — место, где вебка
  обычно стоит на этом стриме.
- **Кто стример.** `core/faceid.py` (ArcFace через onnxruntime) сличает лица
  с эталоном и отбрасывает чужие: из проигрываемого видео, превьюшек,
  аватаров.
- **Раскладка**: `auto`, `split`, `cam` или `screen`. В режиме «Сама решит»
  вебка в углу даёт два блока (вебка 1080×760 сверху, геймплей снизу), вебка
  во весь экран — крупный план, а без вебки экран показывается целиком
  с размытыми полосами.
- **Субтитры** — караоке по словам: текст белый, произносимое слово жёлтое,
  ключевые слова зелёные. Шрифт Arial Black, место — на стыке блоков.
- **Цензура** идёт по словарю `astra/censor.txt` (корни, `*корень*`, исключения
  через `!`). Слово глушится в звуке и маскируется в субтитрах.
- **Кодировщик** выбирается сам. Аппаратные (`h264_nvenc`, `h264_qsv`,
  `h264_amf`) проверяются пробным кодированием трёх кадров. Если ни один
  не работает, рендер идёт через `libx264`, а причина объясняется по-русски.
- Фрагментированный MP4 (записи стримов часто такие) один раз перекладывается
  в обычный контейнер без перекодирования. Иначе ffmpeg для каждого клипа
  заново проходил бы файл с начала.

### 7. Ролики

Длинные ролики собирает `core/roliks.py`, и только из записей Twitch: нужны
главы.

- **По играм.** Twitch хранит в записи главы — моменты, когда менялась
  категория. Игровая глава длиннее порога (по умолчанию 15 минут) становится
  роликом «{стример} играет в {игра}». Короткая вставка другой категории
  посреди игры ролик не рвёт, а та же игра после перерыва короче 10 минут
  склеивается с предыдущей. Граница подтягивается к самому тихому месту
  в пределах минуты.
- **Реакции** (`core/reactions.py`). Разговорные категории (Just Chatting
  и подобные) делятся на реакции: где стример смотрит одно видео, где
  следующее. Граница ищется по смене картинки (ключевые кадры через ffmpeg)
  и голосов, реакция длится не меньше 10 минут. Модель по расшифровке уточняет
  место переключения и называет ролик «{стример} смотрит: {видео}». Название
  видео можно прочитать прямо с экрана моделью со зрением через Ollama
  (по умолчанию `qwen2.5vl:3b`).
- **Сборка.** `clipmaker` вырезает кусок, в конце плавно гасит картинку и звук
  и добавляет размытую концовку под музыку. Кусок и концовка кодируются
  отдельными проходами и склеиваются без перекодирования. Донаты и «отошёл»
  вырезаются изнутри куска.
- **Мут Twitch** (`core/mute.py`, `core/live.py`). Заглушённые места программа
  узнаёт у Twitch (`muteInfo`), а без номера записи ищет полную тишину длиннее
  20 секунд. На эти места кладётся звук из своей записи эфира. Примерное место
  находится по часам, точное — по звуку рядом с мутом, который в обеих записях
  целый. Громкость подгоняется, края сглаживаются.
- **Цензура.** `audioclean` делает вторую копию с заглушённым матом
  (`-c:v copy`, перекодируется только звук). Ролики лежат в папке «с матом»,
  чистые копии — в «без мата» под тем же именем.

### 8. Превью

Превью делает отдельный инструмент `thumbmaker`. Фон — превью исходного видео,
поверх — вырезанный и отзеркаленный стример (MediaPipe Selfie Multiclass).
Кадр с самой яркой эмоцией ищется по блендшейпам лица, внизу крупная подпись
во всю ширину. У инструмента свой веб-интерфейс на Gradio, в автопилот он
не встроен.

### 9. Очередь и выгрузка

Всё смонтированное попадает в очередь профиля (`autopilot.db`) со статусом
«ждёт». На вкладке «Автопилот» клипы можно посмотреть, переименовать, одобрить
или отклонить. Выкладывается **только одобренное**, по одному:

- клип — не чаще раза в `gap_hours` (по умолчанию 6 часов), ролик — не чаще
  раза в `rolik_gap_hours` (24 часа);
- доступ по умолчанию «только мне» (private) и у клипов, и у роликов;
- клипы можно выкладывать на YouTube или TikTok, ролики — только на YouTube.

Выгрузка идёт через [social-auto-upload](https://github.com/dreammis/social-auto-upload)
(`sau`). В репозиторий он не входит. Его ставят отдельно: в
`tools/social-auto-upload`, в `%LOCALAPPDATA%\social-auto-upload`, в домашнюю
папку или туда, куда указывает переменная `ASTRA_SAU`. Ему нужен свой Python
3.10–3.12. Студия вызывает его через мост `core/sau_bridge.py`, который
управляет настоящим браузером: patchright или playwright, а в качестве
браузера Chrome, Edge или встроенный Chromium.

- В аккаунт входят один раз в открывшемся окне браузера. Cookies сохраняются
  в папке `cookies/` у sau.
- На YouTube выкладывается только с видимым окном браузера, трогать его
  не нужно.
- Если Google просит подтвердить личность, выгрузка останавливается и ждёт вас.
- Если на аккаунте несколько каналов, нужный указывается по ID `UC…` или
  `@handle`.
- Просмотры, лайки и даты читаются со страницы YouTube Studio, без API.

История выгрузок хранится в `uploads.db` профиля.

### 10. Чистка

`core/cleanup.py` удаляет только то, что программа сделала сама:

| Что | Когда |
|---|---|
| записи стримов, которые скачала или записала служба | когда всё нарезанное из них решено и прошло `keep_source_days` (2 дня), но не позже `max_source_days` (7) |
| звук эфира в папке `_эфир` | старше `keep_live_days` (7) |
| отклонённые клипы и ролики | через `keep_rejected_days` (2) |
| выложенные клипы и ролики | через `keep_posted_days` (7) |
| кеши разбора (звук, голоса, кадры) | старше недели |

Ваши собственные файлы в папке стримов не трогаются, записи в базах
не удаляются никогда. Чистку запускает служба раз в час, автопилот перед
скачиванием при нехватке места и вы сами кнопкой «Почистить сейчас».

Отдельно у профиля есть срок хранения клипов из ручной нарезки (`keep_days`,
по умолчанию 3 дня). Эта чистка не трогает папки, имя которых начинается
с `_`, и клипы, у которых есть ваша оценка или сравнение.

### 11. Учёба вкуса

Обучающий сигнал берётся из трёх мест.

- **Просмотры своих выгрузок** (`core/taste.py`). Если в первом окне включена
  учёба, Студия раз в сутки обновляет просмотры, берёт клипы с самыми большими
  и самыми маленькими просмотрами в сутки и просит языковую модель
  сформулировать до семи правил вида «брать…» и «не брать…». Правила лежат
  в `taste_rules.json` профиля и добавляются в задание движкам поиска
  по смыслу. Без языковой модели правила не обновляются.
- **Ваши оценки и сравнения** на вкладке «Оценка» (от 1 до 5, «A лучше /
  B лучше») плюс пары, накопленные стадией сравнения. На них
  `py clipper\cli.py train` обучает реранкер: логистическую модель
  Брэдли-Терри по признакам фрагмента. Модель принимается, только если
  на отложенных парах она точнее движка.
- **Связка баз** (`core/learning.py`). Кандидаты clipper сопоставляются
  со смонтированным по источнику и перекрытию во времени.

## Интерфейс

Оформление одно: тёмный фон, жёлтый неон `#fcee0a`, шрифт Bahnschrift.
Палитра и стили ttk заданы в одном месте, в `core/ui.py`. Переходы между
вкладками анимированы, выключить анимации можно переменной `ASTRA_MOTION=0`.

### Первое окно: знакомство

Пока профилей нет, Студия просит имя стримера и **снимок с вебки** — обычный
кадр стрима, где видно человека и комнату. Без снимка профиль не создаётся:
по нему программа находит вебку в кадре и узнаёт стримера.

### Окно запуска: «как будем работать?»

- **Фон — следить за эфиром.** Поле для канала Twitch и кнопка «Свернуть
  в трей». Студия прячется к часам, присылает уведомление о начале эфира
  и пишет звук.
- **Работа со стримом.** Открыть файл стрима, вставить ссылку и скачать
  или просто открыть Студию. Галочка «сразу найти моменты и посчитать, сколько
  выйдет».
- **Учёба на просмотрах.** Галочка «учиться автоматически на новых выгрузках».

Студия запускается в одном экземпляре: повторный запуск будит уже открытое
окно (через локальный порт 47613).

### Главное окно

**Шапка:** выбор профиля, кнопки «Голос и донаты», «Новый», «Удалить».

**Источник** общий для обоих режимов: файл или ссылка, качество (лучшее,
до 1080p, до 720p, только звук), кнопка «Скачать», модель и язык
распознавания, кнопка «Расшифровать» (гаснет, когда расшифровка уже готова).
В строке «Эфир» — канал, кнопка «Писать звук» и галочка «следить и писать звук
эфира».

**Режим «Ролики»:**

| Вкладка | Что там |
|---|---|
| Сборка | Таймкоды (руками или «Из файла»), концовка, музыка и с какой секунды её брать, куда сохранять и сколько хранить. В тонких настройках: громкость музыки, затемнение, размытие, crf, кодирование на видеокарте. Галочка «заглушить мат в готовых роликах», кнопка «Собрать ролики» |
| Цензура | Окно audioclean целиком: найденные слова, прослушивание, ручная правка, глушение тишиной или писком |

| Вкладка | Что там |
|---|---|

| Оценка | Окно оценок clipper: два клипа рядом и кнопки «A лучше / одинаково / B лучше», таблица всех клипов с оценками от 1 до 5 |
| Выгрузка | Площадка и аккаунт, «Войти» и «Проверить», канал, браузер, подключение к уже открытому Chrome по CDP. Список готовых клипов, название, теги, видимость, «Выложить выбранные». «Обновить просмотры», «Правила вкуса» |

Вкладка **«Автопилот»** состоит из карточек:

- **Откуда** — канал Twitch, телеграм-канал с анонсами, «следить за эфирами»,
  «нарезать сразу после эфира», папка стримов, сколько клипов брать со стрима
  и какой длины, «искать по смыслу», «убирать донаты не по теме», «убирать,
  где стример отошёл».
- **Диск** — сроки хранения, минимум свободного места, «Почистить сейчас».
- **Служба** — «Запустить службу», «Запускать с Windows», состояние
  по стримерам.
- **Ролики** — по играм и по реакциям: пороги, шаблоны названий, «читать
  заголовок с экрана», вырезы донатов и «отошёл».
- **Куда** — площадка, аккаунт, канал, доступ, постоянное название,
  расписание клипов и роликов, «выкладывать, пока Студия открыта».
- Кнопки «Проверить стримы и нарезать», «Выложить следующий сейчас»,
  «Запускать сам каждый час» (задача планировщика Windows
  `AstraStudioAutopilot`).
- **Очередь** — «Одобрить», «Отклонить», «Вернуть в ожидание», «Посмотреть»,
  «Переименовать», «Папка».
- **Журнал.**

Внизу главного окна — строка этапа, полоса прогресса, кнопка «Остановить»
и журнал. Если работа длится дольше минуты, процент виден в заголовке окна,
а по окончании окно мигает в панели задач со звуком, если вы на него
не смотрите.

**Окно «Голос и донаты».** Здесь собирается образец голоса стримера
по открытому стриму и хранится список звуков донатов: их можно прослушать
и добавить новый по отрезку. Тут же поиск всех донатов в стриме с разметкой
«это новый звук» или «не донат» и галочки «что делать при нарезке».

### Трей и служба

В трее бывает два значка, и это разные вещи.

- **Студия в фоне** (`studio/tray.py`). Окно спрятано, в меню «Открыть Студию»,
  «Следить за эфиром и писать звук» и «Выход». Крестик в этом режиме окно
  прячет, а не закрывает программу.
- **Служба** (`studio/service_app.pyw` и `core/service.py`) — отдельный
  процесс без окна, сразу для всех профилей. Раз в минуту она перечитывает
  профили: нового стримера подхватывает сама, выключенного отпускает.
  На каждый профиль с Twitch заводится свой сторож. Работа (дождаться записи
  и нарезать, часовая проверка, выгрузка, чистка) идёт одной очередью,
  по одному заданию. В меню — «Открыть Студию», до восьми строк состояния
  и «Остановить службу». Пока идёт запись, на значке горит красная точка.
  Уведомления приходят всплывающими сообщениями трея, журнал пишется
  в `profiles/service.log`. Без pystray служба работает без значка.
  Для автозапуска в папку «Автозагрузка» пользователя кладётся `.vbs`.

Служба запускается в одном экземпляре (замок `profiles/service.lock`).
Без окна её можно запустить из консоли: `py -m core.service`
(`--once` — один шаг и выход).

## Установка и запуск

Общего `requirements.txt` в корне нет. Зависимости разложены по папкам
(`astra/requirements.txt`, `clipper/`, `audioclean/`, `thumbmaker/`),
а `onnxruntime` и `pystray` ни в одном из них не упомянуты.

`Студия.bat` ищет окружение **рядом с репозиторием**, в соседней папке
`..\astra\.venv`. Если его нет, запускается системный `pythonw`. То есть
ожидается такая раскладка:

```
какая-то\папка\
├── astra\.venv\           окружение с библиотеками
└── astra-studio\          этот репозиторий
```

Проще завести окружение самому и ставить всё в него:

```
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r astra\requirements.txt
.venv\Scripts\python -m pip install onnxruntime pystray yt-dlp streamlink
.venv\Scripts\pythonw studio\app.pyw
```

Есть ещё `astra\setup.bat`: он создаёт `astra\.venv` внутри репозитория
и ставит `astra\requirements.txt`. Но `Студия.bat` это окружение не найдёт,
поэтому тогда запускайте `astra\.venv\Scripts\pythonw studio\app.pyw`.

Дальше:

1. Поставьте **ffmpeg**: `winget install Gyan.FFmpeg` или распакуйте сборку
   так, чтобы получилось `ffmpeg\bin\ffmpeg.exe` в папке программы.
2. Для поиска по смыслу поставьте **Ollama** и модель: `ollama pull qwen3:8b`.
   Без неё работают поиск по громкости и эвристика.
3. Для выгрузки поставьте **social-auto-upload** в `tools\social-auto-upload`.
   Если sau не найден, окно само покажет подсказку с командами:

   ```
   git clone https://github.com/dreammis/social-auto-upload.git tools\social-auto-upload
   cd tools\social-auto-upload
   uv venv --python 3.12
   uv pip install -e .
   copy conf.example.py conf.py
   .venv\Scripts\patchright install chromium
   ```

4. Запустите Студию (`Студия.bat` или `pythonw studio\app.pyw`) и создайте
   профиль со снимком вебки. На вкладке «Выгрузка» войдите в аккаунт,
   на вкладке «Автопилот» впишите канал и запустите службу.

Кнопка в Студии запускает службу тем же Python, которым запущена сама Студия.
Поэтому запускайте Студию из окружения с библиотеками: у голого системного
`pythonw` нет `cv2` и остального.

Сборка в `.exe`: `py build_studio.py` (PyInstaller, результат в `build_out/`).

### Переменные окружения

| Переменная | Что задаёт |
|---|---|
| `ASTRA_PROFILES` | Другая папка профилей вместо `profiles/` рядом с программой |
| `ASTRA_STUDIO_SETTINGS` | Другой файл настроек окна вместо `studio/settings.json` |
| `ASTRA_SAU` | Где лежит social-auto-upload |
| `ASTRA_SAU_BROWSER` | Какой браузер отдать выгрузке |
| `ASTRA_MOTION=0` | Выключить анимации |
| `OLLAMA_HOST` | Адрес Ollama |
| `CLIPPER_WORK`, `CLIPPER_BACKEND`, `CLIPPER_LOCAL_MODEL`, `CLIPPER_OPENAI_URL`, `CLIPPER_OPENAI_KEY`, `CLIPPER_COMPARE…` | Рабочая папка и настройки clipper, полный список в `clipper/README.md` |

### Тесты

```
py tests\run.py            все наборы (54)
py tests\run.py studio     только наборы, в имени которых есть «studio»
py tests\media.py          собрать тестовые видео и показать, где они лежат
```

Тестовые видео и речь собираются сами (ffmpeg и системный синтезатор речи
Windows) и кешируются во временной папке. Наборы, которым нужны `cv2`,
`mediapipe` и faster-whisper, `run.py` запускает интерпретатором
из `..\astra\.venv` или `astra\.venv`, если такой найдётся. Сеть в тестах
подменена, поэтому выгрузку с настоящими аккаунтами и внешний вид окна они
не проверяют. Долгий `studio_sense_test.py` в общий прогон не входит.

В `tests/snapshot/` лежат снимки поведения до и после правок ядра, а `spy.py`
подставляет вместо модели распознавания «шпиона», который записывает
параметры вызова.

## Нюансы и ограничения

- **Рассчитано на Windows.** Окна без консоли, планировщик `schtasks`,
  автозапуск через `.vbs`, звук `winsound`, `.bat`-файлы.
- **Профили живут в папке программы** (`profiles/Имя/`): `profile.json`, снимок
  вебки, `clips/`, `clips.db`, `autopilot.db`, `uploads.db`, правила вкуса,
  образцы голоса и звуков донатов. Папка `profiles/` в git не попадает: там
  личные данные и обучающий сигнал каждого стримера. Профили со старого места
  (`%LOCALAPPDATA%\astra-studio`) переезжают сами при первом запуске.
- **Не в git:** `profiles/`, `tools/` (social-auto-upload с cookies входа),
  `cookies/`, `accounts/`, `*.token`, базы `*.db` и `*.sqlite3`, медиафайлы,
  `studio/settings.json`. Не передавайте эти папки вместе с программой.
- **Выкладывается только одобренное, по умолчанию с закрытым доступом.**
  Доступ «для всех» нужно выбрать явно.
- **Мут Twitch закрывается только в роликах** и только если служба писала звук
  эфира. В шортсах заглушённые места остаются тихими.
- **Ролики по играм и реакции делаются только из записей Twitch**, потому что
  нужны главы. Из записей с других площадок, сделанных по анонсу, режутся
  только клипы.
- **Поиск по смыслу и реакции требуют расшифровки всего стрима** — это самая
  долгая часть. Поиску по громкости она не нужна.
- **Кеши лежат рядом с исходником:** `*.speech.json` (расшифровка),
  `*.probe.json` (ffprobe), `*.muted.json` (мут), кеши звука и уровней,
  перекладки `*.seekable.mp4`. Перекладка весит столько же, сколько стрим.
  Посмотреть и убрать: `py clipper\cli.py cache` (`--clean`, `--remux`, `--all`).
- **Запись стрима весит 30–50 ГБ.** Держите папку стримов на быстром диске
  с запасом места; порог `min_free_gb` по умолчанию 60 ГБ.
- **MediaPipe не открывает модели по пути с не-ASCII символами.** Модель
  копируется во временную папку с латинским именем (`core/models.py`).
  По той же причине yt-dlp получает короткое имя 8.3 для файла сертификатов,
  если в пути есть кириллица.
- **`.bat` пишутся только в ASCII:** cmd читает файл побайтово до `chcp`.
- **Видеокарта NVIDIA.** `h264_nvenc` может числиться в ffmpeg и при этом
  не работать, если драйвер старше, чем требует сборка ffmpeg. Программа
  проверяет это пробным кодированием, переходит на процессор (`libx264`)
  и объясняет причину. После обновления драйвера видеокарта подхватится сама.
- **Расшифровка в монтаже astra не детерминирована.** astra не передаёт
  `condition_on_previous_text=False`, поэтому текст на одном и том же файле
  может немного отличаться от запуска к запуску. Clipper и audioclean передают
  свои параметры VAD. Так сделано намеренно, чтобы не менять распознанный
  текст.
- **Словарей мата два.** У audioclean матчер сильнее: снимает маскировку
  латиницей и цифрами, ловит фразы, склеивает разорванные слова. У astra
  он проще, по корням. Поэтому в шортсе и в ролике могут глушиться разные
  слова.
- **Маленькие модели не держат шкалу от 0 до 10**, поэтому порядок задаёт
  сравнение, а не оценка. Пустой ответ движка — нормальный результат,
  а не ошибка.
- **На YouTube выкладывается только с видимым окном браузера.** Если Google
  просит подтвердить личность, выгрузка ждёт человека. Название для YouTube —
  не длиннее 100 знаков. Видимость в TikTok задаётся на самом сайте.
- **Просмотры читаются со страницы YouTube Studio**, а не через API. Если
  Studio поменяет вёрстку, чтение может сломаться.
- **Телеграм — только публичные каналы:** читается веб-страница `t.me/s/…`.
- **Превью (`thumbmaker`) живёт отдельно** на Gradio и в автоматический
  конвейер не входит.
- **Стиль кода:** комментариев и docstring почти нет, интерфейс и сообщения
  на русском. Находки, добытые замерами, собраны в README папок
  (`core/README.md`, `clipper/README.md` и другие).
